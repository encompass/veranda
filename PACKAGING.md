# Packaging Veranda

Veranda ships packaging definitions for **Flatpak**, **Snap**, and **Debian**.
All three install the same desktop-integration files from `data/`
(`*.desktop`, `*.metainfo.xml`, the icon, the GNOME Shell search-provider
`.ini`, and the udev rule) and the Python app from `pyproject.toml`.

> **Device access caveat (read this first).** Veranda talks to two kernel
> devices: the Stream Deck over USB/hidraw, and `/dev/uinput` for the Hotkey
> and Type Text actions (Wayland-safe key injection). USB/HID works in every
> format. `/dev/uinput` is the sticking point under sandboxing — see each
> section. On the host you still want the udev rule from
> `data/60-veranda-streamdeck.rules` so the device is usable without root.

The recommended distribution channel is **Flatpak** — the GNOME-native path,
which bundles GTK4/libadwaita/PyGObject via the GNOME runtime and the Python
dependencies into one self-contained app.

---

## Flatpak

Manifest: `flatpak/com.encompass.Veranda.yaml`.

```bash
flatpak install -y flathub org.gnome.Platform//48 org.gnome.Sdk//48
flatpak-builder --user --install --force-clean build flatpak/com.encompass.Veranda.yaml
flatpak run com.encompass.Veranda
```

- The `python-deps` module fetches `streamdeck`, `Pillow`, and `evdev` from
  PyPI during the build (it requests `--share=network`). This is fine for local
  and CI builds. **For a Flathub submission**, replace that module with a
  pinned, hashed one generated by
  [`flatpak-pip-generator`](https://github.com/flatpak/flatpak-builder-tools):
  ```bash
  flatpak-pip-generator streamdeck Pillow evdev   # -> python3-modules.json
  ```
  and reference the generated file instead (Flathub forbids network at build).
- `--device=all` grants `/dev` access for both the Stream Deck **and**
  `/dev/uinput`, so key injection works inside the sandbox. The host still needs
  the udev uaccess rule for non-root device access.

## Snap

Recipe: `snap/snapcraft.yaml` (uses the `gnome` extension for
GTK4/libadwaita/PyGObject).

```bash
snapcraft                              # -> veranda_0.1.0_amd64.snap
sudo snap install --dangerous ./veranda_*.snap
```

- **Confinement is `strict`.** The Stream Deck works via the `raw-usb` /
  `hardware-observe` / `hidraw` plugs, but there is **no strict-mode interface
  for `/dev/uinput`**, so the **Hotkey and Type Text actions will not work**
  under strict confinement.
- If key injection matters, switch to `confinement: classic` (commented in the
  recipe). Classic grants full host access — uinput works — but classic snaps
  require manual review to publish on the Snap Store.
- After install, connect the device interfaces if they aren't auto-connected:
  ```bash
  sudo snap connect veranda:raw-usb
  sudo snap connect veranda:hardware-observe
  ```

## Debian / Ubuntu (.deb)

Packaging: `debian/` (dh-python / pybuild).

```bash
sudo apt build-dep .        # or install the Build-Depends from debian/control
dpkg-buildpackage -us -uc -b
sudo apt install ../veranda_0.1.0-1_all.deb
```

- Runtime deps resolve from the archive (`python3-gi`, `gir1.2-gtk-4.0`,
  `gir1.2-adw-1`, `python3-pil`, `python3-evdev`, `libhidapi-libusb0`).
- `python-elgato-streamdeck` ("streamdeck") is **not in Debian**, so
  `debian/rules` vendors it into the package via `pip` at build time. This
  needs network access during the build (drop a pre-downloaded wheel into the
  target dir for an offline buildd).
- The package installs the udev rule to `/lib/udev/rules.d`; `postinst` reloads
  udev so the device is usable without a reboot. Key injection works natively
  (no sandbox) once the user is in the `input` group or a uinput udev rule is in
  place — see the README.

## Where the files come from

| Installed file | Source in repo |
| --- | --- |
| `…/applications/com.encompass.Veranda.desktop` | `data/com.encompass.Veranda.desktop` |
| `…/metainfo/com.encompass.Veranda.metainfo.xml` | `data/com.encompass.Veranda.metainfo.xml` |
| `…/icons/hicolor/scalable/apps/com.encompass.Veranda.svg` | `src/veranda/icon.svg` |
| `…/gnome-shell/search-providers/…ini` | `data/com.encompass.Veranda.search-provider.ini` |
| `/lib/udev/rules.d/60-veranda-streamdeck.rules` | `data/60-veranda-streamdeck.rules` |
| `/usr/bin/veranda` (console script) | `pyproject.toml` `[project.scripts]` |

The copies embedded in `src/veranda/` (icon, metainfo, CSS) are the same files,
bundled into the wheel so the running app can self-install desktop integration
in a development checkout (`autostart.py`). `data/com.encompass.Veranda.metainfo.xml`
mirrors `src/veranda/com.encompass.Veranda.metainfo.xml`; keep them in sync.
